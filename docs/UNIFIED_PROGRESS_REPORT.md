## 2. Milestone log

### M1 — Secret vault completion + credential broker (security/infrastructure, priority A)
- **Implemented:** vault lock/unlock with failure throttling, opt-in idle lock, revoke tombstones, emergency shutdown that survives restart (owner-approved resume only), encrypted backup package (scrypt + AES-256-GCM, header as AAD, content-bound restore approval, revoked credentials not revived without a separate approval subject), encrypted audit anchor (truncated/replaced audit log keeps the vault locked), stale-file-copy detection bound to ciphertext hashes. Credential broker: agents never receive a raw secret; owner-signed per-grant approvals; exact HTTPS hosts/paths/methods; rate limits; kill-switch gate; audit-before-send; response redaction in common encodings; cross-instance grant reload. Owner-auth nonce store now checks-and-appends under a file lock (cross-process replay).
- **Tests:** `atlasz-tests/m1-vault-broker.test.mjs` (35), `atlasz-tests/m1-round2.test.mjs` (11). Synthetic secrets and a fake fetch only; no network. Full regression suite 1136/1136 passing, 52/52 independent probes, mutation checks on the new guards (survivors equivalent: crash-window `ever` guard, `wx` open after unlink, unlocked-persist guard in single-process runs), secret scan of the diff clean.
- **Independent verification:** round 1 (14 findings, fixed in 21ede48); round 2 (3 HIGH, 5 MEDIUM, ~10 LOW; fixes in this commit). A round-3 narrow check is still recommended before any claim beyond PARTIAL.
- **Requirement movement:** 23-point #1 (vault) and #3 (broker) advance but **remain PARTIAL**. No 85/150 classification changes.
- **Not done / honest gaps:** no Control Center panel; idle lock off by default; no provider-side secret rotation; broker is not wired as an agent tool (agent-tool-policy denies unlisted tools); audit chains are unkeyed sha256 (tamper-evident, not tamper-proof); redaction covers common encodings only; a rolled-back audit log bricks the vault until recovery from a backup (fail-closed by design).

### M2 — C01 code-edit / repair workflow (software development and repair, priority C)
- **Implemented:** `atlasz-addons/code-edit-workflow.mjs`: propose (nothing written) -> review by a DIFFERENT agent (static code review; FAIL blocks) -> apply with a single-use owner approval bound to the exact change digest; byte-exact snapshot (modes, created folders) pinned in the audit chain; intent recorded before the approval is spent; writes tmp+rename with post-hash verification; sandboxed tests via the existing REPO_TEST_RUN gate; failing tests restore the snapshot only for files still holding this change's output (never over someone else's edits); owner rollback (plain or explicitly partial); crash recovery; withdraw/expiry/quotas; bounded repair chain (3 attempts); truth in a hash-chained audit log, record files treated as untrusted. Wired into `createRuntime` (status + `rt.codeEdit`); no agent tool exposes it.
- **Tests:** `atlasz-tests/m2-code-edit-workflow.test.mjs` (29 tests incl. runtime hosting and a real restricted-launcher run). Independent verification: round 1 (9 findings) and round 2 (5 follow-ups) from a fresh worktree agent that never read the tests; all fixed with regression tests; mutation checks on the guards (survivors are redundant defence-in-depth or need real cross-process timing).
- **Requirement movement:** C01 (85 registry) gains the missing edit workflow but stays PARTIAL (no model-driven authoring, no git/PR integration by design, no agent tool wiring, no Control Center panel). PKG150 SN02/S506/OP02/OP04/S502 advance partially. 23-point item on controlled code change advances partially. No classification changes.
- **Known limits:** identities (author/reviewer) are asserted by the caller and must be bound to the authenticated agent when a tool is wired; audit chain is tamper-evident not tamper-proof (tail truncation by someone with write access to the state folder is not detected here); non-UTF-8 files are refused; rotating author ids can fill the global open-change cap until expiry; a local attacker racing the project folder between a path check and a rename is not defended beyond lstat checks.

### M3 — Markdown memory + FTS5 + hybrid retrieval (memory and knowledge, priority D)
- **Implemented:** `atlasz-addons/memory-store.mjs`: Markdown notes are the truth (front matter, body hash, atomic writes); a rebuildable index uses `node:sqlite` FTS5 (BM25) with an in-memory lexical fallback; local hashed n-gram similarity fused with BM25 by RRF. Classification PUBLIC/PERSONAL/CONFIDENTIAL with reader clearance (hidden notes look like missing ones); SECRET content refused/scrubbed; retrieved text fenced as UNTRUSTED_MEMORY; bad files quarantined; declassify and forget need single-use owner approvals bound to note+body hash; hash-chained audit; note cap. Wired into `createRuntime` (status + `rt.memoryStore`); no agent tool exposes it.
- **Tests:** `atlasz-tests/m3-memory-store.test.mjs` (22 tests, both backends); mutation checks on scrub/cap guards. Independent fresh-worktree verification round 1: 9 findings (0 critical/high; prototype-key classes, hand-edit declassify, byte-size quarantine, duplicate oracle, fence escape, forget leaving versions, secret-filter gaps, DB-locked under multi-process use, load-time cap) - all fixed with regression tests; round 2 re-check found 5 follow-ups in the fixes (class floor lost on forget, SQLite lock mistaken for damage, secret filter over-refusing prose, fence run-collapse gap, title/tags/source outside the fence), fixed (44 tests); round 3 (author-only class raise, normalised credential-assignment filter, audit de-dup, batched reindex) fixed (46 tests); **round 4 (narrow re-check, 2026-10-10): 2 MEDIUM (credential names `SECRET_KEY`/camelCase/German/Hungarian/look-alike letters not recognised; quadratic scan in the assignment regex), 4 LOW (prose false positives, caller-asserted author on class raise, audit de-dup reset by mtime, existence/hash oracle on owner-only subject helpers) - the two MEDIUM and the prose false positives are fixed with regression tests (linear scan, folded look-alikes, camelCase split, `name is value`, prose-vs-credential rules); the remaining LOW are documented limits.** M3 stays **PARTIAL until a further narrow re-check of the round-4 fixes returns no HIGH/MEDIUM** (see M5 section).
- **Requirement movement:** Markdown memory / FTS5 / hybrid-search items advance PARTIAL only. No classification changes.
- **Known limits:** similarity is lexical n-gram, NOT neural embeddings; `node:sqlite` is experimental and may be absent in Electron (fallback exists); single tenant per directory; no agent tool or Control Center panel; audit chain unkeyed; a hand edit can raise but never lower a class (floor taken from the audit chain, so an attacker who rewrites both note and audit file is out of scope); title/tags/source are returned as plain fields and must be treated as untrusted by consumers; `write` takes a caller-asserted `clearance` for the duplicate check.

### M4 — Agent coordination (multi-agent, priority B)
- **Implemented:** `atlasz-addons/agent-coordination.mjs` (orchestration logic, **not** an agent; roster stays exactly 5 SEARCH + 25 EXECUTION): identity-bound frozen handles from the roster only; task-bound, participant-only, fenced messaging (SEARCH-to-SEARCH goes through the coordinator); delegation through the handoff ledger with team/kind rules, depth and rejection caps and no hand-back to a previous owner; coordinator-assigned independent verifier chosen by duty (never an owner, never one that already failed); loop and runaway controls (hop cap, per-thread and per-task budgets with a per-sender share, repeated-message and ping-pong detection with directional pair blocks, rate limit, mailbox caps); bounded sub-agents (`SUB-<parent>-<8hex>`: <=2 per parent, <=10 global, spawn rate, TTL, message/step budgets, tool subset of the parent, die with the task, cannot spawn); owner-only secret-scanned hash-verified checkpoints and task recovery; stalled-work reclaim (max 3, then abandon); kill-switch freeze; hash-chained audit; persisted hash-checked state with strict shape validation. Hosted in `createRuntime` (screening becomes a coordinated task that a DIFFERENT execution agent re-checks; advisory, it does not gate the pipeline).
- **Tests:** `atlasz-tests/m4-agent-coordination.test.mjs` (26) + M4 round-3 regressions in `m5-verification-round1.test.mjs`; mutation checks on every guard.
- **Independent verification:** round 1 (7 findings), round 2 (8 findings) fixed; **round 3 (2026-10-10): 0 HIGH, 2 LOW-MEDIUM, 1 LOW** - a task whose whole team already owned it could wait for a checker forever (now abandoned), routine notes could lock an agent out of escalating (escalations have their own cap), restarts more often than the stall threshold hid real stalls (only real downtime is credited back now); sub-agent budget validation added. The `onVerified` hook was attacked and held (fires only on a real ACCEPT by a different agent; a throwing hook cannot undo a verification).
- **Requirement movement:** 85-registry C03 (multi-agent coordination), P08/P16 (continuation) and PKG150 GE02/GE03 advance, **classifications unchanged (PARTIAL)**. 23-point items on agent communication/permissions advance partially.
- **Known limits:** identities outside handles are caller-asserted; state hash and audit chain are unkeyed (tamper-evident, not tamper-proof); nothing in the runtime reads the coordinator mailbox yet (the Control Center does not show it); maker-checker for screening reads the same persisted record as the maker; no cross-process lock on the coordinator state file (one runtime process owns it).

### M5 — Agent memory integration, Control Center memory panel, embedding retrieval plumbing (memory and knowledge, priority D)
- **Implemented:**
  - `atlasz-addons/agent-memory.mjs`: the only door between the 30 agents and the memory store - identity-bound frozen handles; agent-private / project / tenant scopes (reserved tags cannot be forged, tags snapshotted once); clearance ceilings for reading AND writing; long-term and operational (TTL) memory; instruction-lookalike and secret refusal; quotas and rate limits; agents can only ASK to forget their own notes (owner decides with a signed, note-bound approval); `recordVerifiedWork` is the only way a `prov-verified` note appears and is called only from the coordinator's verified hook (no external title text is copied); task-time retrieval (`contextFor`) only for task participants and fails closed without a participation check; hash-chained access log without raw query text; restart-safe state shared with the Control Center.
  - `memory-store.mjs` additions: `reader.allow` (can only narrow), `retireBatch` (retention sweep bound to the exact ids AND body hashes), forget/declassify/retention subject helpers, optional semantic provider (`reindexSemantic`, `searchAsync`, `semanticStatus`), class floor and audit view that follow other processes.
  - `embedding-provider.mjs`, `semantic-index.mjs`, `retrieval-eval.mjs`: runtime/hardware detection (no network), candidate model table, loopback-only Ollama adapter with validated output, owner-signed activation record, integrity-hashed multi-writer vector index, relevance metrics. The toy fixture is labelled `TEST_FIXTURE ... NOT neural` everywhere; only a real `NEURAL` provider yields a `NEURAL_EMBEDDINGS(model)` label; any provider problem degrades to lexical and says so.
  - Runtime hosting (`rt.agentMemory`, dashboard), verified-work hook, task-time retrieval (`cand.relatedMemory`), background bounded reindex when a provider is active.
  - Control Center: `atlasz-control-center/memory-panel.mjs`, `GET /api/memory`, `POST /api/memory/action`, Memory view (notes with scope/class/provenance, search with per-mode scores, source/author/class on open, agent activity, access log, pending forget requests, retention preview/sweep, lower class, forget, add owner note, index/backend/semantic status, embedding hardware + candidate table, activate/deactivate, diagnostics). Owner-affecting actions are signed from the keystore passphrase and bound to the exact subject; a refusal inside a result is shown as a failure, never "done".
- **Tests:** `m5-memory-integration.test.mjs` (18), `m5-runtime-memory.test.mjs` (5), `control-center-memory.test.mjs` (6), `m5-verification-round1.test.mjs` (20); full suite and 52/52 independent probes pass (see the final report below); mutation checks on all new guards (survivors documented: equivalent defence-in-depth only).
